# 协作流程

本文档介绍团队日常协作与代码提交流程。

## Git 工作流

团队采用 Git Flow 简化版：主分支 main 保持可发布状态，开发从 main 拉取 feature 分支，功能完成后提交 Merge Request 合并回 main。分支命名规范为 feature/xxx、fix/xxx。

## Merge Request 流程

提交 MR 后需要至少一名同事 Code Review 通过才能合并。MR 描述必须写清改动内容、测试情况和影响范围。合并前必须通过 CI 自动检查和单元测试。

## Code Review 规范

评审关注代码可读性、边界条件处理、性能隐患和安全问题。评审意见分为必须修改和可选建议两档，必须修改项解决后才能合并。

## 需求协作流程

需求由产品经理在 TAPD 建立，开发评审排期后进入开发。联调阶段与后端约定接口，测试通过后提交测试验收，最后由发布负责人发布上线。
