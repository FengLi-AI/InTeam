## 二、产品概述

### 2.1 产品背景

新员工加入企业后，需要在较短时间内理解公司业务、岗位要求、当前项目、团队协作方式和常用流程。这些信息通常分散在不同资料中，检索成本高，且缺少一条从“了解信息”到“开始行动”的连续路径。

当新员工遇到具体问题时，常见处理方式是自行翻找资料或反复询问同事。前者效率较低，后者会增加团队重复答疑成本。即使得到答案，新员工也可能仍不清楚下一步应该做什么。

InTeam 将企业知识库、AI 问答、上手地图和行动计划整合在同一工作台中，帮助新员工持续完成“提问—理解—确认行动—完成事项”的入职过程。

### 2.2 产品定位

**InTeam 是面向企业新员工的 AI 入职助手。用户可以用自然语言询问公司、岗位、项目、协作和流程问题，获得基于企业资料生成的回答；Agent 同时结合对话内容提出候选行动，由用户确认后加入个人入职计划。**

### 2.3 产品价值

| 对象 | 产品价值 |
|---|---|
| 新员工 | 减少资料查找和重复确认，更快理解企业信息并明确下一步行动 |
| 带教与协作团队 | 减少常见问题的重复答疑，将精力留给需要人工判断的事项 |
| 企业 | 将分散的入职资料转化为可检索、可问答、可持续维护的知识服务 |

### 2.4 产品目标

1. 帮助新员工建立对企业、岗位、项目、协作方式和常用流程的整体认知。
2. 基于企业知识回答具体问题，并在资料不足时清楚说明信息边界。
3. 根据对话内容生成可选择的下一步行动建议。
4. 通过上手地图、行动状态和完成进度形成持续推进的入职闭环。

## 三、目标用户与使用场景

### 3.1 目标用户

主要用户为处于入职适应和业务上手阶段的企业新员工。

企业实施与知识维护人员负责准备企业资料、维护知识库和配置 Agent 工作流。

### 3.2 核心使用场景

1. **了解企业与业务**：询问企业定位、产品、客户、价值观等信息。
2. **理解岗位要求**：了解岗位职责、阶段目标和工作重点。
3. **熟悉当前项目**：了解项目背景、目标、模块、进度和风险。
4. **掌握协作方式**：了解团队协作规范、沟通路径和问题升级方式。
5. **查询常用流程**：询问请假、报销、出差、远程办公和权限申请等流程。
6. **推进个人行动**：查看 Agent 建议，将合适的建议加入计划并持续完成。
7. **连续追问**：围绕同一主题进行多轮对话，在上下文中继续获得回答。

### 3.3 核心用户故事

- 作为新员工，我希望直接用日常语言提问，而不需要先知道资料名称和存放位置。
- 作为新员工，我希望回答能够以企业资料为依据，并明确哪些信息可以确认。
- 作为新员工，我希望在得到答案后看到适合执行的下一步建议。
- 作为新员工，我希望自己决定哪些建议进入计划，并能管理行动状态。
- 作为新员工，我希望刷新或再次进入产品后，上手进度和行动计划能够保留。

## 四、产品原则

### 4.1 企业知识优先

涉及企业、岗位、项目、制度和流程的事实，以企业知识库的有效检索结果为依据。资料不足时，只回答能够确认的部分，并明确提示信息边界。

### 4.2 Agent 提建议，用户做决定

Agent 负责提供候选行动，行动只有在用户明确点击“加入计划”后才成为正式事项。行动完成、恢复、编辑和删除均由用户操作。

### 4.3 从回答走向行动

产品不仅帮助用户理解“是什么”，还通过候选行动和进度联动帮助用户明确“下一步做什么”。

### 4.4 员工端清晰，服务端可追踪

员工端聚焦问题、回答和行动。检索过程、工作流节点、模型配置和运行日志由服务端与 Dify 管理，用于维护、排查和效果评估。

### 4.5 真实状态反馈

系统以真实请求状态、流式内容和保存结果驱动界面反馈。候选建议、正式行动和已完成事项使用清晰不同的状态表达。

## 五、产品信息架构

### 5.1 桌面端结构

```text
┌──────────────────────────────────────────────────────────────────┐
│ 顶部：InTeam 品牌 / 企业标识 / 产品名称                           │
├────────────────┬──────────────────────────────┬──────────────────┤
│ 上手地图        │ AI 入职 Agent                │ 入职推进          │
│                │                              │                  │
│ 今日开始        │ 欢迎状态与推荐问题             │ 今日重点          │
│ 公司与业务      │ 多轮对话                       │ Agent 建议        │
│ 我的岗位        │ 流式回答                       │ 我的行动          │
│ 当前项目        │ 追问建议                       │ 完成进度          │
│ 团队与协作      │ 回答反馈                       │                  │
│ 常用流程        │ 自适应输入框                   │                  │
└────────────────┴──────────────────────────────┴──────────────────┘
```

- 中央 Agent 为默认主区域和主要视觉焦点。
- 左右面板各自滚动，中央对话区独立滚动。
- 左右面板宽度可在桌面端进行有限调整，中央区域保持主要阅读空间。

### 5.2 移动端结构

移动端采用单栏布局，通过底部导航切换三个入口：

1. **问 Agent**：默认入口，完成提问、多轮对话、停止生成、重试、追问和反馈。
2. **上手地图**：查看六个入职主题、当前进度和推荐问题。
3. **我的计划**：查看今日重点、Agent 建议、个人行动和完成进度。

三个入口使用同一份用户进度和行动数据。

## 六、核心业务流程

```text
浏览上手地图
    ↓
选择推荐问题或主动提问
    ↓
检索企业知识并流式生成回答
    ↓
展示追问建议与候选行动
    ↓
用户确认加入计划或暂不需要
    ↓
管理并完成个人行动
    ↓
同步行动进度与上手主题状态
```

### 6.1 地图提问流程

1. 用户展开一个上手主题。
2. 用户点击主题中的推荐问题。
3. 系统将该主题从“未开始”更新为“了解中”。
4. 问题进入中央 Agent，并自动发起问答。
5. 回答完成后刷新候选行动与主题进度。

### 6.2 主动提问流程

1. 用户在输入框中输入问题并发送。
2. 界面依次展示理解问题、检索知识、梳理回复等状态。
3. 回答以流式方式逐步呈现。
4. 回答完成后展示可用的追问建议和候选行动提示。
5. 用户可以继续追问或提交回答反馈。

### 6.3 行动推进流程

1. Agent 根据回答内容生成候选行动。
2. 候选行动进入右侧“Agent 建议”。
3. 用户选择“加入计划”或“暂不需要”。
4. 已加入的事项进入“我的行动”，并参与“今日重点”和完成进度计算。
5. 用户完成、恢复、编辑或删除行动后，相关区域同步刷新。

## 七、详细功能需求

### 7.1 上手地图

#### 7.1.1 功能说明

上手地图按主题组织新员工需要建立的核心认知，并通过推荐问题将主题直接连接到 Agent 对话。

#### 7.1.2 固定主题

| 主题 | 内容范围 |
|---|---|
| 今日开始 | 首日准备与近期优先事项 |
| 公司与业务 | 企业定位、产品、客户和工作价值观 |
| 我的岗位 | 岗位职责与阶段性上手目标 |
| 当前项目 | 项目背景、目标、模块、进度和风险 |
| 团队与协作 | 协作规范、沟通路径和问题升级方式 |
| 常用流程 | 请假、报销、出差、远程办公和权限申请等流程 |

#### 7.1.3 内容与状态

每个主题包含：

- 主题名称。
- 一句话说明。
- 至少 3 个推荐问题。
- 当前状态。
- 关联的未完成行动数量。

主题状态包括：

| 状态 | 含义 |
|---|---|
| 未开始 | 用户尚未通过该主题提问或主动调整状态 |
| 了解中 | 用户已经开始了解，或仍有该主题下的未完成行动 |
| 已完成 | 用户主动标记完成，或该主题下已确认行动全部完成 |

#### 7.1.4 交互要求

- “今日开始”首次进入时默认展开。
- 各主题可以独立展开或收起。
- 点击推荐问题后直接切换到 Agent 并发送问题。
- 用户可以主动标记主题完成，也可以将已完成主题恢复为“了解中”。
- 主题状态和关联行动数量在操作成功后同步刷新。

#### 7.1.5 验收标准

- 六个主题均可正常展开和收起。
- 推荐问题可以成功发起 Agent 对话。
- 主题状态更新成功后即时显示，刷新页面后仍然保留。
- 关联行动状态变化后，主题状态与行动数量同步更新。

### 7.2 AI 入职 Agent 问答

#### 7.2.1 功能说明

用户在中央区域输入自然语言问题，系统通过 Dify 工作流检索企业知识并生成回答，由 InTeam 服务端统一转换为稳定的流式事件返回前端。

#### 7.2.2 首屏状态

- 展示 InTeam Agent 中央视觉图形。
- 展示问候语“今天想了解点什么？”。
- 展示产品能力说明。
- 展示 4 个推荐问题，点击后直接发起对话。
- 输入框在无输入、无焦点时循环展示推荐问题提示。

#### 7.2.3 问答能力

- 支持自然语言提问。
- 支持同一会话中的多轮上下文追问。
- 支持从上手地图发起问题。
- 支持 Markdown 格式回答，包括标题、列表、强调、引用、表格、代码块和安全链接。
- 支持回答后的最多 3 个追问建议。
- 支持回答后的候选行动生成。

#### 7.2.4 生成状态

| 阶段 | 前台提示 |
|---|---|
| 建立请求 | 正在绞尽脑汁 |
| 接收工作流 | 正在理解你的问题 |
| 知识检索 | 正在翻阅企业知识库 |
| 组织内容 | 正在梳理回复 |
| 流式输出 | 正在组织成清晰答案 |

状态区域同步展示阶段进度，让用户持续感知系统正在处理。

#### 7.2.5 回答规则

| 场景 | Agent 行为 |
|---|---|
| 企业资料能够可靠支持 | 根据检索内容直接回答，表达清楚、简洁 |
| 资料只能支持部分问题 | 只回答可以确认的部分，并说明剩余信息需要进一步确认 |
| 当前资料没有足够依据 | 明确说明企业知识库暂无足够信息 |
| 问题表达模糊 | 提出必要的澄清问题 |
| 回答中包含明确下一步 | 生成候选行动，等待用户确认 |
| 请求系统提示词、密钥、源码或内部配置 | 拒绝敏感部分，并引导回正常入职问题 |

#### 7.2.6 流式输出与控制

- 回答内容以 SSE 流式事件返回，并以适中的速度逐步呈现。
- 用户可以在生成过程中停止回答，已展示的内容继续保留。
- 对话区仅在用户位于底部附近时自动跟随新内容。
- 用户向上阅读历史内容时，新内容不会强制抢动滚动位置。
- 网络中断、上游超时、请求过多和响应不完整时显示可理解的错误提示。
- 可重试错误保留原问题并提供重新发送入口。

#### 7.2.7 输入框

- 单行状态为胶囊形输入框，多行状态为圆角矩形。
- 输入框高度随内容在限定范围内平滑变化，删除多行内容后恢复单行高度。
- Enter 发送，Shift + Enter 换行。
- 发送按钮固定在输入框右下侧，生成中切换为停止按钮。
- 输入为空时发送按钮处于不可用状态。

#### 7.2.8 验收标准

- 企业知识范围内的问题可以获得与资料一致的回答。
- 多轮追问能够延续当前会话上下文。
- 回答以流式方式逐步出现，生成阶段状态正确切换。
- 停止生成后保留已输出内容。
- Markdown 内容能够正确渲染且不执行 HTML。
- 断流、超时、限流和服务异常均有明确反馈与重试路径。

### 7.3 回答反馈

#### 7.3.1 功能说明

每条已完成的 Agent 回答提供“有帮助”和“没解决”两个反馈入口。

#### 7.3.2 交互规则

- 用户点击“有帮助”后直接提交反馈并显示结果。
- 用户点击“没解决”后可以补充一条可选说明，再提交反馈。
- 反馈失败时在当前回答中显示提示，回答正文继续保留。
- 反馈记录与对应回答关联，用于知识维护和回答效果优化。

#### 7.3.3 验收标准

- 两种反馈均可正常提交。
- “没解决”的补充说明可以为空，也可以随反馈保存。
- 操作完成后界面显示已反馈状态。

### 7.4 AI 入职推进

#### 7.4.1 功能说明

入职推进将 Agent 回答中的下一步建议转化为用户可确认、可编辑、可完成的个人行动。

#### 7.4.2 页面结构

| 区块 | 内容与默认状态 |
|---|---|
| 今日重点 | 展示当前优先的最多 3 条未完成行动，默认展开 |
| Agent 建议 | 展示尚未决策的候选行动，默认收起 |
| 我的行动 | 展示用户已经确认加入计划的全部行动 |
| 完成进度 | 按已完成行动数与全部行动数计算百分比 |

#### 7.4.3 Agent 建议

每条候选建议包含：

- 建议时间提示：今天、3 天内、本周或暂不设日期。
- 关联的上手主题。
- 行动标题。
- 建议原因。
- “加入计划”和“暂不需要”操作。

候选建议只有在用户明确确认后才进入“我的行动”。同一条候选建议重复确认时保持结果幂等。

#### 7.4.4 我的行动

每条行动包含：

- 行动标题。
- 行动状态：待完成或已完成。
- 确认日期，可为空。
- 来源于用户确认的 Agent 建议。
- 关联上手主题，可为空。

用户可以：

- 完成行动。
- 恢复已完成行动。
- 编辑行动标题和日期。
- 删除行动，删除前进行二次确认。

#### 7.4.5 今日重点与进度

- 今日重点从未完成行动中选取最多 3 条。
- 已设置且日期较早的行动优先展示。
- 完成进度按照“已完成行动数 ÷ 全部行动数”计算。
- 暂无正式行动时进度显示为 0%。

#### 7.4.6 联动规则

- Agent 回答完成后，候选建议列表自动刷新。
- 候选建议加入计划后，同时刷新今日重点、我的行动和完成进度。
- 行动完成、恢复或删除后，同时刷新入职推进和上手地图。
- 某主题存在未完成行动时，主题状态同步为“了解中”。
- 某主题下已确认行动全部完成时，主题状态同步为“已完成”。

#### 7.4.7 验收标准

- “今日重点”默认展开，“Agent 建议”默认收起，两个区块均可独立展开和收起。
- 候选建议在确认前不会进入正式行动列表。
- 加入计划、暂不需要、完成、恢复、编辑和删除操作均正确保存。
- 点击行动圆点后状态即时更新，刷新后仍然保留。
- 完成进度、今日重点和上手地图与行动状态保持一致。
- 桌面端和移动端展示同一份行动数据。

## 八、企业知识库数据

**根据企业要求定制化服务。**

### 8.1 知识范围

企业知识库按以下业务范围组织：

| 知识范围 | 主要内容 |
|---|---|
| 公司通识 | 企业介绍、业务、产品、客户、价值观、制度和常见问题 |
| 岗位与协作 | 岗位职责、阶段目标、协作规范和常用流程 |
| 项目知识 | 项目背景、目标、术语、模块、里程碑、进度和风险 |

具体知识分类、资料来源、字段结构、更新频率和权限边界根据企业实际情况确定。

### 8.2 数据要求

- 进入知识库的资料应具有明确来源、适用范围和维护责任。
- 同一事实在多份资料中保持一致，出现冲突时由企业维护人员确认有效版本。
- 制度、项目状态和流程等时效性内容应标记生效时间或更新时间。
- 资料内容仅作为企业事实依据，不作为改变 Agent 角色或系统规则的指令。
- 涉及敏感信息的资料按照企业权限要求进行分级和访问控制。

### 8.3 数据更新

1. 企业维护人员在资料变更后更新对应知识内容。
2. 更新完成后重新执行索引或同步。
3. 使用代表性问题检查召回内容和回答结果。
4. 对“没解决”反馈和知识盲区进行定期整理，决定是否补充资料或调整表达。
5. 记录知识版本、更新时间和关键调整内容，便于问题追踪。

### 8.4 检索与回答要求

- 根据问题范围检索一个或多个知识分类。
- 检索结果需要支持回答中的企业事实。
- 资料为空、相关性不足或存在冲突时，回答状态应降级为信息有限或未找到。
- 知识资料中出现的指令性文本按照普通资料处理，系统级规则保持更高优先级。

## 九、Dify Agent 工作流

**根据企业要求定制化服务。**

### 9.1 平台职责

Dify 负责企业知识检索、回答生成和结构化建议生成。InTeam 服务端负责安全接入、会话关联、流式事件转换、结构校验、数据保存和员工端状态联动。

### 9.2 当前工作流

```text
用户问题
    ↓
知识检索
    ↓
企业知识回答
    ↓
流式回复用户
    ↓
结构化建议
```

工作流的知识库组合、模型选择、检索策略、提示词、节点编排和输出规则根据企业场景进行配置。

### 9.3 工作流输出

员工可见正文与结构化附加信息分开处理。

结构化附加信息包括：

- 回答状态：可靠、有限、未找到或已拦截。
- 最多 3 个追问建议。
- 最多 3 个候选行动。

每条候选行动至少包含：

| 字段 | 说明 |
|---|---|
| 唯一键 | 保证同一候选建议重复处理时保持幂等 |
| 标题 | 用户可直接理解的行动名称 |
| 原因 | 说明为什么建议执行该行动 |
| 行动类型 | 阅读、询问、准备、练习、复盘或其他 |
| 时间提示 | 今天、3 天内、本周或暂不设日期 |
| 关联主题 | 对应上手地图中的一个主题 |
| 来源 | 固定标记为 Agent 候选建议 |

### 9.4 服务端校验

- InTeam 服务端只接收约定工作流节点产生的结构化建议。
- 所有结构化字段经过类型、长度、枚举值和主题范围校验。
- 附加信息缺失或校验失败时，已生成的回答正文继续正常完成。
- 通过校验的候选行动先保存为待决策状态，经用户确认后再创建正式行动。
- Dify 内部任务 ID、节点信息、模型配置和密钥保留在服务端。

### 9.5 会话与流式事件

- InTeam 为每个本地会话维护对应的 Dify 会话标识。
- 服务端将 Dify 事件转换为 `status`、`chunk`、`replace`、`done` 和 `error` 五类稳定事件。
- 前端停止生成时只提交 InTeam 请求标识，由服务端定位并停止对应的上游任务。
- 回答完成后保存问题、正文、回答状态和候选建议关联关系。

### 9.6 知识维护与发布

- 企业资料在 Dify 知识库中更新并重新索引。
- 工作流调整后先进行节点测试和代表性问题验证，再发布新版本。
- 每次发布保留可回退的工作流导出文件。
- API Key 仅保存在服务端环境配置中。

## 十、核心数据对象与状态

### 10.1 数据对象

| 对象 | 核心字段 | 用途 |
|---|---|---|
| 上手主题 | 主题标识、标题、说明、推荐问题 | 组织入职认知路径 |
| 主题进度 | 主题标识、状态、更新时间 | 保存用户的上手进度 |
| 对话会话 | 本地会话标识、Dify 会话标识 | 维持多轮上下文 |
| 对话消息 | 问题、回答、回答状态、完成状态 | 保存问答结果 |
| 候选行动 | 唯一键、标题、原因、时间提示、关联主题、决策状态 | 保存 Agent 建议 |
| 正式行动 | 标题、状态、日期、来源、关联主题 | 保存用户确认后的行动 |
| 回答反馈 | 回答标识、反馈结果、补充说明 | 支持效果评估和知识维护 |

### 10.2 状态关系

```text
候选行动：待决策 → 已接受
                 ↘ 已忽略

正式行动：待完成 ↔ 已完成

上手主题：未开始 → 了解中 ↔ 已完成
```

### 10.3 数据一致性规则

- 候选行动、正式行动、反馈和主题进度按当前使用者隔离保存。
- 状态写入成功后再更新完成提示与关联区域。
- 接受同一候选建议时保持幂等，避免生成重复行动。
- 删除行动后重新计算今日重点、完成进度和关联主题状态。
- 服务异常时保留用户当前输入和页面已有数据。

## 十一、服务接口范围

| 方法 | 路径 | 产品用途 |
|---|---|---|
| GET | `/api/v1/onboarding-map` | 获取六主题上手地图与进度 |
| POST / PATCH | `/api/v1/onboarding-map/{topic_key}` | 更新主题状态 |
| POST | `/api/v1/chat` | 发起企业知识问答并返回 SSE |
| POST | `/api/v1/chat/{request_id}/stop` | 停止当前回答生成 |
| GET | `/api/v1/actions` | 获取今日重点、候选建议、行动和进度 |
| POST | `/api/v1/actions` | 接受候选建议并创建正式行动 |
| POST / PATCH | `/api/v1/actions/{id}` | 编辑行动或更新完成状态 |
| DELETE | `/api/v1/actions/{id}` | 删除行动 |
| POST | `/api/v1/actions/{id}/delete` | 在仅开放 GET / POST 的部署环境中删除行动 |
| POST | `/api/v1/suggestions/{id}/dismiss` | 忽略候选建议 |
| POST | `/api/v1/feedback` | 提交回答反馈 |

接口错误统一转换为员工可理解的产品提示。服务端日志保留请求标识、错误类型、处理耗时和必要的关联信息。

## 十二、视觉与交互要求

### 12.1 整体风格

- 整体采用轻量、克制、具有科技感的企业产品风格。
- 页面以白色和低饱和蓝紫色为主，内容层保持清晰的前后层级。
- 使用 MiSans 字体，正文采用较轻字重，关键信息使用常规或加粗字重。
- 问答卡片与输入区使用半透明磨砂玻璃效果。
- 顶部区域保持透明，并保留下方浅色分隔线。

### 12.2 布局与滚动

- 页面主体固定在可视区域内，避免整体页面被纵向拖动。
- 左栏、中栏和右栏使用各自的内部滚动区域。
- 左右侧滚动条使用低透明度主题色。
- 中央对话滚动条在滚动时渐显，停止滚动后渐隐。
- 内容上下溢出处使用渐隐遮罩，减少硬切割感。
- 输入框与左右面板底部在桌面端保持对齐。

### 12.3 动效

- 首次进入时，问候语使用折叠文字与流光文字效果出现。
- 输入框边框使用低强度光晕反馈焦点状态。
- 背景由静态底图、低透明度 Aurora 图层和 Aero Shards 图层组成。
- Aero Shards 保持缓慢运动，并支持按住指针后聚拢和跟随。
- 所有布局变化、折叠展开和输入框高度变化使用连续缓动。
- 系统遵循设备的“减少动态效果”设置，降低或停止非必要动效。

### 12.4 响应式

| 屏幕范围 | 布局要求 |
|---|---|
| 桌面端 | 三栏同时展示，左右栏可调整有限宽度 |
| 平板端 | 中央 Agent 为主，辅助区域按可用空间切换 |
| 移动端 | 单栏展示，通过底部导航切换三个核心模块 |

移动端输入框、底部导航和可滚动内容应适配安全区域，避免互相遮挡。

## 十三、安全、性能与可维护性

### 13.1 安全要求

- 企业知识和用户行动数据按照企业的数据与访问要求进行隔离。
- Dify API Key、服务端密钥、工作流内部标识和日志信息仅保存在服务端。
- 用户输入执行长度校验、频率限制和 Prompt 注入检测。
- Markdown 渲染跳过 HTML，仅允许安全的 HTTPS 链接。
- 停止生成、行动更新、行动删除和反馈提交均校验数据归属。
- 日志避免记录密钥、完整认证信息和无必要的敏感正文。

### 13.2 性能与稳定性

| 项目 | 要求 |
|---|---|
| 首屏体验 | 基础布局和可交互区域优先完成加载 |
| 问答反馈 | 请求发出后立即出现阶段状态 |
| 流式回答 | 收到正文后持续增量展示，避免整段突然出现 |
| 状态保存 | 行动与进度操作完成后及时刷新相关区域 |
| 异常恢复 | 断流、超时、限流和上游错误均有提示与重试入口 |
| 响应式 | 桌面端、平板端和移动端的核心流程均可完成 |

### 13.3 可维护性

- 前端、InTeam 服务端和 Dify 工作流职责清晰分离。
- 知识数据、工作流配置和应用密钥分别管理。
- 数据结构变更通过数据库迁移执行。
- 工作流结构化输出使用固定契约校验。
- 关键问答、候选行动和状态联动具备自动化测试与回归用例。

## 十四、效果评估

### 14.1 核心指标

| 指标 | 统计口径 |
|---|---|
| 企业知识回答准确率 | 代表性问题中，回答与有效企业资料一致的比例 |
| 信息边界正确率 | 资料不足时，正确降级并避免补充未经资料支持事实的比例 |
| 回答完成率 | 成功完成流式回答的请求数占有效请求数的比例 |
| 回答帮助率 | “有帮助”反馈数占已提交反馈数的比例 |
| 建议接受率 | 被加入计划的候选行动数占已决策候选行动数的比例 |
| 行动完成率 | 已完成行动数占正式行动总数的比例 |
| 上手主题完成度 | 已完成主题数占六个主题的比例 |

### 14.2 评估要求

- 使用独立于知识原文表达的问题集验证检索和回答效果。
- 评估覆盖公司通识、岗位与协作、项目知识、跨范围问题和资料未收录问题。
- 每次知识库或工作流重要调整后执行回归测试。
- 静态结构校验与真实问答评估分别记录，真实通过率以实际运行结果为准。

## 十五、核心验收场景

### 15.1 上手地图

1. 首次进入工作台，“今日开始”默认展开。
2. 展开其他主题后，原主题状态保持稳定。
3. 点击推荐问题，系统切换到 Agent 并自动发起对话。
4. 主动标记主题完成后，完成数量和状态正确更新。

### 15.2 企业知识问答

1. 提问企业资料中已有的问题，返回与资料一致的流式回答。
2. 连续追问同一主题，回答延续当前上下文。
3. 提问资料不足的问题，系统明确说明信息边界。
4. 生成过程中点击停止，已显示内容保留。
5. 模拟断流或超时，界面显示错误并允许重试。
6. 回答中的 Markdown 标题、列表和表格正确渲染。

### 15.3 候选行动与入职推进

1. 回答完成后产生候选行动，“Agent 建议”数量同步更新。
2. 点击“加入计划”，候选行动进入“我的行动”。
3. 点击“暂不需要”，候选行动从待决策列表移除。
4. 点击行动圆点，行动显示为已完成并更新进度。
5. 再次点击已完成行动，行动恢复为待完成。
6. 编辑行动标题和日期，保存后刷新页面仍然保留。
7. 删除行动后，今日重点、进度和关联主题同步更新。

### 15.4 回答反馈

1. 点击“有帮助”，提交成功并显示已反馈状态。
2. 点击“没解决”，填写可选说明后提交成功。
3. 模拟提交失败，界面显示失败提示且保留原回答。

### 15.5 响应式体验

1. 桌面端三栏可以独立滚动，输入框与左右面板底部对齐。
2. 移动端可以在“问 Agent”“上手地图”“我的计划”之间切换。
3. 输入多行文字后再删除，输入框平滑恢复单行状态。
4. 底部导航和输入框不会遮挡主要内容。

## 十六、产品总结

**InTeam 通过企业知识库、AI 入职问答、六主题上手地图和用户确认的行动计划，帮助新员工从一个真实问题开始，逐步完成理解企业信息、明确下一步和推进个人入职行动的完整闭环。**
