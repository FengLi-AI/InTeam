## 4. 协作流程事实

| 事实 ID | 主题 | 统一事实 |
|---|---|---|
| PROC-001 | 需求入口 | 新需求先进入 FlowPilot Intake，必须附来源、原始证据、问题描述和影响范围 |
| PROC-002 | 需求澄清 | 产品经理先区分事实、推测与待确认内容，再组织 30 分钟澄清会 |
| PROC-003 | 方案评审 | 评审材料至少提前 1 个工作日发布，包含目标、非目标、流程、风险和验收标准 |
| PROC-004 | 决策记录 | 评审结论在当日写入 NovaWiki 决策记录，并关联 FlowPilot 事项 |
| PROC-005 | 变更控制 | 已进入开发的范围变化必须记录原因、影响和确认人，不允许只在聊天中口头变更 |
| PROC-006 | 发布门槛 | 产品验收、测试通过、监控与回滚方案齐备后才能发布 |
| PROC-007 | 阻塞升级 | 阻塞超过 4 个工作小时先同步导师或模块负责人；影响里程碑时当天升级给陈默 |
| PROC-008 | 沟通格式 | 推荐使用“背景—事实—影响—需要谁在何时确认什么”的结构 |

3. 未出现在本表中的企业事实视为“未收录”，Agent 不得用模型常识补全。
4. 人员姓名、联系方式和项目数据全部为虚构；不加入真实邮箱、手机号、客户名或密钥。
